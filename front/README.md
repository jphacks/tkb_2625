# ROAM — ロゲイニング参加者アプリ

`docs/prompt.md` をもとにした、レビュー用のReactプロトタイプです。オリーブ・生成り・砂色を基調に、角丸のないモバイルファーストのUIを実装しています。

## 配置

このディレクトリが参加者向けフロントエンドのルートです。既存の client・appview とは独立した npm プロジェクトとして管理します。以下のコマンドは front 内で実行してください。

```powershell
cd ~/GitHub/tkb_2625/front
```

## 起動

Node.js 22.12以上（動作確認環境：24.20.0）を使用してください。

```powershell
npm.cmd ci
npm.cmd run dev
```

表示されたローカルURL（通常は http://localhost:5173 ）をブラウザで開いてください。依存パッケージはインストール済みです。PowerShellの実行ポリシーで `npm.ps1` がブロックされる環境でも使えるよう、コマンドは `npm.cmd` で記載しています。macOS/Linuxでは `npm` に読み替えてください。

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

`build` の成果物は `dist/` に生成します。外部ホスティングには公開していません。静的ホスティングする場合は、`/cards` などのパスを `index.html` にフォールバックする設定が必要です。

## レビュー手順

1. `/cards`：全9件、4ステータスを確認します。375px幅では3列、350px未満では2列です。「不可」「審査中」などの絞り込みと並び替えを試してください。
2. 未提出の「緑の歩道橋」を開き、画像なしで提出してエラーを確認します。JPEG・PNG・WebPの画像を選択し、プレビューから提出してください。8MBを超える画像は受け付けません。
3. `/admin`：提出した画像を承認してください。初期ポイント80ptに40ptが加算され、ヘッダー・カード・チーム画面で120ptになります。同じ提出は再審査・重複提出できません。
4. 「不可」の「森の喫茶室」から再提出し、管理画面で理由を入力して不承認にしてください。再提出できることと、`/team` に以前の履歴が残ることを確認します。
5. `/map`：デモのチェックポイント・破線の経路・デモ位置を確認します。実測GPSに切り替えて「記録開始」で位置取得を開始できます。停止または画面の離脱で監視を解除します。
6. `/admin` 下部の「大会を終了する」で、タイマーが0となり写真を提出できなくなることを確認します。
7. 再読み込みして履歴・画像・終了時刻が保持されることを確認します。「デモを初期化」で80pt、4ステータス、残り3時間の状態に戻せます。

初期データの「広場の大樹」には、不承認後に再提出して審査中となった履歴を用意しています。モーダルはネイティブの `dialog` を使い、Escape・閉じるボタン・背景クリックで閉じられます。画像処理中は閉じる操作を制限しています。

## 実装範囲と仮定

| 項目 | 内容 |
| --- | --- |
| 大会 | 架空の代々木エリア大会。チーム・名前・位置・配点はサンプル |
| 参加チーム | 1チーム、3名。メンバー編集・ランキングは範囲外 |
| 終了時刻 | 初回起動／デモ初期化から3時間。再読み込みでは延長しない |
| 写真提出・審査 | 同じブラウザのローカルデータで動作。管理画面も実装済み |
| 画像 | 目標・初期提出画像は自作SVGイラスト。実際の撮影対象を示す写真ではない |
| 保存 | localStorageに履歴・提出画像・終了時刻を保存。画像は長辺1200px以下のJPEGへ変換 |
| 保存容量 | ブラウザの容量制限あり。保存失敗は表示し、その操作を状態に反映しない |
| GPS経路 | 実測とデモを区別。実測経路は画面内のメモリのみ。離脱／再読み込みで消去 |
| 同期 | サーバー接続・複数端末／複数タブの同期なし。レビューは同じタブ内で実施 |
| 認証 | 未実装。`/admin` は保護されていないデモ画面 |

参加者画面と管理画面は共通の状態を参照します。ポイントは承認済みチェックポイントのIDを重複排除して計算し、再提出前の不承認履歴は保持します。バックエンド導入時は `src/repository.js` の取得・保存境界と、`src/data.js` の提出・審査処理をサーバー側APIへ移してください。大会終了・重複提出・権限の検証もサーバー側で必要です。

## 地図と端末機能

- [Leaflet](https://leafletjs.com/reference) と [OpenStreetMap標準タイル](https://operations.osmfoundation.org/policies/tiles/)を利用しています。APIキーは不要です。地図内にOpenStreetMap contributorsの帰属表示を掲載しています。ネットワーク接続が必要で、背景地図の取得に失敗すると案内を表示します。
- GPSにはHTTPSまたはlocalhostと、ユーザーの位置情報許可が必要です。スマートフォンからPCのLANアドレスにHTTP接続した場合、画面のレビューは可能でもGPSが使えない場合があります。実機GPSの確認にはHTTPS環境を使用してください。
- GPSの取得は「記録開始」時のみです。拒否・未対応・取得失敗時は案内を表示し、デモ表示に戻せます。
- 地図は北が上です。端末の方位は「端末の方位を確認」でセンサー値が取得できたときだけ度数を表示します。未取得や権限拒否時に架空の方向を表示しません。
- バックグラウンド記録や端末スリープ中のGPS継続は保証していません。

## 構成

```text
src/
  App.jsx         共通ヘッダー、カード、詳細モーダル、チーム、管理者
  MapPage.jsx     Leaflet地図、GPS・方位センサーと監視解除
  data.js         サンプル、ステータス、提出・審査・ポイント計算
  repository.js   保存処理、画像形式・容量確認と縮小
  styles.css      Tailwind読み込み、配色・レイアウト・レスポンシブ
tests/
  domain.test.js      状態遷移、終了制限、並び替え、重複加算防止
  repository.test.js  保存往復、破損データ、容量不足、無効ファイル
```

React・React Router・Viteを使用し、Tailwind CSSは[公式のViteプラグイン](https://tailwindcss.com/docs/installation/using-vite)で組み込んでいます。
