# ROAM client

React・TypeScript・Viteで実装した、ロゲイニングの参加者画面と管理者モックです。

## 起動

Node.js 24、pnpm 11 を使用します。リポジトリ直下から実行してください。

```powershell
cd client
corepack.cmd pnpm@11.0.0 install --frozen-lockfile
corepack.cmd pnpm@11.0.0 dev
```

表示されたURLを開くと `/cards` へ移動します。macOS/Linuxでは `corepack.cmd` を `corepack` に読み替えます。

```powershell
corepack.cmd pnpm@11.0.0 typecheck
corepack.cmd pnpm@11.0.0 build
corepack.cmd pnpm@11.0.0 preview
```

成果物は `client/dist/` に生成します。静的配信では `/cards`・`/team`・`/map`・`/admin` への直接アクセスを `index.html` にフォールバックさせてください。

## 画面

- `/login`：独立したログイン画面。「AT Protocolでログイン」は表示用のモックで、押すと準備中の案内を表示します。認証・通信・他画面への遷移は行いません。既存画面からのリンクも追加していません。
- `/events`：`listEvents` のイベントをカード表示します。開催状況での絞り込み、イベント名・主催者名の検索、再取得、各大会のランキングへの移動に対応します。
- `/cards`：チェックポイントの一覧、絞り込み・並び替え、写真選択・提出・再提出。
- `/events`：イベント一覧。「すべて／開催予定／開催中／終了」のタブで `listEvents` の `status`（省略／`upcoming`／`ongoing`／`ended`）を切り替えます。大会名・主催者名の検索にも対応します。
- `/team`：チーム情報、承認済みポイント、提出履歴。
- `/map`：Leafletによるチェックポイント・デモ経路の表示、任意操作でのGPS記録と方位取得。
- `/ranking`：`listEvents` で大会を選択し、`getRanking` のチーム順位・メンバー・獲得ポイント・達成CP数を表示します。順位はAPIの集計結果をそのまま使い、ログイン中のDIDが所属するチームを「あなたのチーム」として強調します。
- `/admin`：管理画面。ランキングへ移動します。
- `/admin/ranking`：全チームのメンバー・獲得ポイント・順位。同点は同順位。
- `/admin/teams`：チームの追加・削除、参加者の所属変更・解除。
- `/admin/checkpoints`：CP番号・名前・配点・見本写真・緯度経度の登録・削除。地図クリックでも位置を指定できます。
- `/admin/map`：全チームのモック位置とCP。チーム絞り込み、位置未取得・最終更新日時の表示。
- `/admin/review`：全チームの写真審査。承認・理由付き不承認、大会終了、デモ初期化。

管理画面上部の「参加者モックの表示チーム」で、参加者画面に表示するチームのカード・得点・提出履歴を切り替えられます。切り替え後、URLを直接入力して `/cards` を開くと表示を確認できます。管理画面から参加者画面への遷移リンクはありません。参加者画面にはこの切り替えを表示しません。初期状態は3チーム・8名（うち未所属1名）です。

道草クラブの初期ポイントは80ptです。「緑の歩道橋」の写真を提出して `/admin/review` で承認すると、各画面の得点が120ptになります。得点はチームごとに、承認されたCPの配点を重複なく加算します。

## イベントの開催状況フィルター

`/events` のタブを選ぶとAPIを再取得します。URLは `/events?status=upcoming`・`ongoing`・`ended` となり、再読み込みやブラウザの戻る／進むでも選択状態を復元します。「すべて」は `status` を送信しません。不明な値は「すべて」として扱い、APIには送りません。

タブはクリック・Tab／Enter・左右矢印・Home／Endで操作できます。取得中・取得失敗・再試行・該当イベントなしを表示し、切り替え前の遅い応答は反映しません。実データの取得には、既存の `LexClientProvider` で接続先と認証を設定する必要があります。
## イベント一覧

参加者メニューの「イベント」、または `/events` を直接開きます。`listEvents` のレスポンス順で、イベント画像・大会名・主催者・開催日時（日本時間）・説明・参加チーム数・参加者数・CP数を表示します。画像なし／画像取得失敗時は代替表示にし、未提供の参加数は0と区別して「—」で表示します。

「開催予定」「開催中」「終了」を選ぶと、`listEvents` の `status` パラメーターで絞り込みます。URLは `/events?status=ongoing` などとなり、直接アクセスや戻る操作にも対応します。名前検索は取得済みの一覧に対して行います。「ランキングを見る」は対象大会のURIを `/ranking` へ引き継ぎます。

実データの取得には、ランキングと同様に適切な接続先・認証を持つClientを `LexClientProvider` へ渡す必要があります。APIエラー時にローカルの管理者モックへ置き換えることはありません。取得中・該当なし・取得失敗・再試行の表示を用意しています。

## 参加者ランキング

参加者メニューの「ランキング」、または `/ranking` を直接開き、大会を選択します。`/ranking?event=<URLエンコードした大会AT-URI>` でも大会を直接指定できます。取得中・未選択・参加チームなし・エラー・再試行に対応しています。大会を切り替えた場合、前の大会の遅い応答は反映しません。

`getRanking` が返した順位・得点・達成CP数をそのまま表示します。「自分」は `LexClientProvider` の認証済みClientのDIDと、順位表のチームメンバーのDIDを照合して判定します。該当行には背景色と「あなたのチーム」を表示し、「自分の行へ」で移動できます。未ログイン・所属チームなしの場合は他チームを自分として表示しません。

現在の `LexClientProvider` の既定値は未認証・同一オリジンへの接続です。実データの取得には、サービス認証に対応したClientをProviderへ渡す必要があります。このページではOAuthログインやバックエンドの変更は行いません。管理者モックのローカル順位データとは独立しており、API取得失敗時にモックの順位へ置き換えることもありません。

## 管理画面の確認手順

1. チーム管理でチームを追加し、参加者を割り当てます。管理画面上部で追加チームを選び、同じタブで `/cards` を直接開いてメンバーが反映されることを確認します。
2. CP管理で見本写真と位置を指定してCPを登録します。参加者のカード・地図と、管理者の位置マップで同じCPを確認できます。
3. 参加者から写真を提出し、写真審査で承認します。ランキング・チーム管理・参加者画面に得点が反映されます。他チームの履歴や得点には影響しません。
4. CPを削除すると、そのCPの全チームの提出履歴と得点も削除されます。チームを削除すると、そのチームの提出履歴・得点を削除し、メンバーを未所属へ戻します。いずれも削除前に確認を表示します。
5. 再読み込みすると、チーム・所属・CP・提出履歴・表示チームが復元されます。「写真審査」のデモ初期化で全体を初期状態に戻せます。

## データと端末機能

バックエンド接続はなく、チーム・場所・画像はサンプルです。管理者と参加者は同じタブ内の状態を共有します。IndexedDBの `roam-demo` データベースに、状態を `state`、画像のBlobを `images` に分けて保存します。状態には画像IDだけを持たせるため、チーム切り替えのたびに全画像をbase64でシリアライズすることはありません。

同じオリジンに旧localStorageの `roam-demo-v2` または `roam-demo-v1` があれば初回に移行します。v1の写真・審査結果・終了時刻は道草クラブへ引き継ぎ、ほかのチームのサンプル履歴も保持します。画像と状態は同一トランザクションで保存し、旧localStorageのデータは削除・上書きしません。移行済みの場合、以後はIndexedDBを読み込みます。異なるポート・別端末・複数タブの同期、認証はありません。

IndexedDBが使えない場合は警告を表示し、メモリ上の一時デモとして操作を続けられます。この場合、再読み込みで変更は失われます。通常の永続化モードで容量不足などの保存失敗が起きた場合は、操作を反映せずエラーを表示します。IndexedDBにも端末依存の容量制限があります。

管理者のチーム位置は日時付きの固定モックで、参加者のデモ地図も同じ位置を表示します。位置未取得のチームには架空の現在位置を割り当てません。実測GPSの共有・追跡・バックエンド連携は行いません。

写真はJPEG・PNG・WebPの8MBまで対応し、長辺1200px以下のJPEGに縮小します。再提出前の不承認画像は履歴として保持します。CP削除・チーム削除・デモ初期化で参照されなくなった画像は、状態の更新と同じトランザクションで削除します。

地図はLeafletとOpenStreetMap標準タイルを使用し、APIキーは不要です。出典は地図内に表示します。背景タイルにはネットワーク接続が必要です。

GPSはHTTPSまたはlocalhostと位置情報許可が必要です。経路は地図画面内だけで保持し、停止・離脱時に監視を解除します。一時的なタイムアウトや測位失敗では記録を継続して次の測位を待ち、権限拒否時は停止します。方位センサーは対応端末でのみ利用できます。カメラ・GPS・方位の動作は実端末で確認してください。

写真提出やチーム追加は、GPSとは別にHTTPのLAN接続でも動作します。スマートフォンから画面を確認するには `corepack.cmd pnpm@11.0.0 dev --host 0.0.0.0` で起動し、表示されたLANアドレスを開きます。HTTPのLAN接続では実測GPSは使えないため、GPS確認にはHTTPS環境を使用してください。

`src/lexicons` と既存の `gen:lexicon` コマンドはそのまま利用できます。
